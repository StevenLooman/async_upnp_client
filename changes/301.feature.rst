Add uint32 rollover handling to IGD traffic rate counters.

The existing rate fields on ``IgdState`` (``kibibytes_per_sec_received``,
``kibibytes_per_sec_sent``, ``packets_per_sec_received``, ``packets_per_sec_sent``)
now correctly handle 32-bit counter rollover instead of returning ``None`` when the
counter wraps around.

Four new ``IgdStateItem`` variants are added for callers that want the old
rollover-unaware behaviour (returning ``None`` on rollover):
``KIBIBYTES_PER_SEC_RECEIVED_NO_ROLLOVER``, ``KIBIBYTES_PER_SEC_SENT_NO_ROLLOVER``,
``PACKETS_PER_SEC_RECEIVED_NO_ROLLOVER``, and ``PACKETS_PER_SEC_SENT_NO_ROLLOVER``.

Two new methods are also added to ``IgdDevice``:

* ``async_poll_traffic_data()`` — polls the current raw traffic counters from the device.
* ``build_igd_state()`` — derives an ``IgdState`` (including the rollover-aware rates)
  from two ``TrafficCounterState`` snapshots.

**Backwards compatibility:** code that reads ``IgdState`` fields by name or uses
``IgdStateItem`` members by name continues to work. The rate fields now return a value
where they previously returned ``None`` on rollover — callers that relied on ``None``
to detect a counter reset should switch to the new ``_NO_ROLLOVER`` variants. Code that
constructs ``IgdState`` positionally or unpacks it by position will also need updating
for the four new fields.
